# LP-DiD analytic degrees of freedom: panel-wide → contributing clusters (2026-09-16)

**What was wrong.** `.re_lpdid()` in `R/power/run_estimators.R` took its t-inference degrees of freedom from `run_estimator()`'s `df_cluster <- cl$n_total - 1L` (line 336), the count of every state in the simulated panel. A state can be placed in `panel_sim` yet contribute zero rows to the stacked regression — the COVID gap sitting inside its baseline window, or a series ending before its cohort's launch+12 outcome month — so the analytic CI and p-value were computed with more clusters than the estimation sample held. The overstatement makes `qt()` smaller, narrowing the CI in the over-rejection direction. Found in the 2026-09-16 implementation review (`quality_reports/lpdid_sim_implementation_review_2026-09-16.md`, item G).

**Fix.** Inside `.re_lpdid()`, after the stack is built and filtered to finite weights, `df_lp <- max(1L, length(unique(stack$state_abb)) - 1L)`; the analytic row's `z` and `.re_tp()` now use `df_lp`. The wild row is untouched (boottest supplies p and CI); early-return error rows still carry `cl`. Regression test: `tests/testthat/test-estimators.R` — "lpdid analytic CI uses stack-contributing clusters, not panel-wide states" (fails on the old code, passes on the new; all 18 estimator tests pass).

**Scope of impact.** Only LP-DiD **analytic** rows. Magnitude is small — with ~33 panel states and materially fewer contributing, the t-critical shifts on the order of 1–2%. Every LP-DiD analytic size/MDE number computed before 2026-09-16 (including the FINDINGS §2 "analytic LP-DiD passes the gate in both weightings, 0.045/0.048" decision point) used the panel-wide df and is slightly anti-conservative; the wild numbers, which are the standing headline, are unaffected. Any post-2026-09-16 analytic LP-DiD run needs a fresh `run_name` (scenario ids hash settings, not code).

**Not changed.** `n_treated_clusters` / `n_control_clusters` still report placed, not contributing, states (the residual span-vs-presence gap noted in FINDINGS §5). The other estimators (`.re_twfe`, `.re_cs`, `.re_did2s`, `.re_bjs`, `.re_sunab`, `.re_ldam`) still use `df_cluster`; for those the estimation sample is the whole panel, so the count is right.

**Pre-existing test failure noted in passing.** `tests/testthat/test-grid.R` — "exclude_states drops the states from the simulated panel" — fails with `NA` cluster counts on the current working tree with `run_estimators.R` reverted to HEAD, so it is unrelated to this fix (likely the uncommitted panel-rebuild changes).
