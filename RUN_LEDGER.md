against). Full evidence for any row lives in the linked inventory file, not repeated here.

## Status vocabulary

| Status | Meaning |
|---|---|
| **LIVE** | Current best number for its question. Citable as-is. |
| **SUPERSEDED** | Valid when run, replaced by a later run. Points to its replacement — never delete the row. |
| **CONTAMINATED** | Invalid due to a specific, named bug or stale input (see boundary dates below). Not just old — wrong. |
| **DEAD** | The number itself is invalid (a bug in the computation), or the run never produced a usable result (empty/abandoned). |
| **EXPLORATORY** | Completed, not contaminated, but not a headline/decision-relevant number — descriptive, a probe, or a one-off diagnostic. |
| **UNKNOWN** | No producing script found, or genuinely ambiguous status. Flagged for human review, not guessed at. |

## The seven vintage boundary dates

Nearly every contamination reason below reduces to "this ran before one of these fixes":

1. **2026-07-23** — NH + ME court-source repairs (before this, ME is excluded or carries a zero-fill artifact; NH carries a −57% coverage artifact).
2. **2026-08-10 ~16:16** — treatment-schedule repair (ME, VT, KY, FL, DE, NC, MO gained online-legalization dates; before this they are misclassified as never-treated).
3. **2026-08-20 ~01:26** — state-panel double-count rebuild (`state_month_panel_with_treatment.csv` had summed county totals + an overlapping ETS state series for 12 states). Only `level: state` runs are affected — county-download-based runs are immune.
4. **2026-08-21 ~10–17h** — Nevada-exclusion audit (`PRE_PASPA_SPORTS_BETTING`). NV is always-treated since 1949 and absent from the schedule CSV, so it silently sat in the never-treated control pool of state-level D1 designs until this fix.
5. **2026-08-24** — LP-DiD reweighting fix. The pre-fix default (`cellsize` weights) was neither of Dube-Girardi-Jordà-Taylor's two named estimands (EWATT, VWATT). Every `lpdid`-estimator row computed before this date is a dead estimand, even where the same run's TWFE/did2s/LDAM rows remain valid.
6. **2026-08-28 ~17h** — per-state basket-start rebuild (`data_prep/rebuild_state_month_panel.R`). The 2026-08-20 fixed-basket rule required counties to report from the GLOBAL 2016-01 window start, silently excluding every state whose county series begins later; the required-month set is now per state. Adds CO, HI, MS, NY, SC (34 → 39 states; NY and CO are treated). **Every pre-existing state-month is unchanged bit-for-bit** — this boundary is a pure sample extension, but state-level runs still need a fresh `run_name` (sample composition changed; scenario ids hash settings, not data). Pre-rebuild panel: `data/raw/deprecated/state_month_panel_with_treatment_globalbasket_2026-08-20.csv`.
7. **2026-09-03** — Maryland series extension (`data_prep/monthly_panel_expansion/07b_extend_md_in_panel.R`). MD was clipped at 2025-11 by the one-shot 07_ merge (which trims MD to the panel's extent at merge time and ran before the 08-20/08-28 rebuilds); a refresh of the MD statistics PDFs (01b/01c) carried the parsed source to 2026-06. Appends MD 2025-12..2026-06 (7 months, all post-treatment). **Every pre-existing row — MD and non-MD — is unchanged bit-for-bit** (asserted in-script), so this is a pure series extension. The added months land in the panel's thin tail, where only NC was previously present; MD and NC are both treated, so these months carry no untreated comparison and contribute nothing to identification under any FE estimator. State-level runs still need a fresh `run_name`. Pre-extension panel: `data/raw/deprecated/state_month_panel_with_treatment_pre_md_extend_2026-09-03.csv`.

## THE MAINTENANCE RULE

> **Every completed run appends one row to the matching table before the session ends.
> A superseded row is never deleted — its status changes and points to its replacement.**

See [Adding a row](#adding-a-row) at the bottom for the template.

**Infrastructure landmines (2026-08-25).**
> - **`lpdid_anchor` default has drifted.** Reproducing the live `lpdid_shift12_gate_ewatt` run requires pinning `lpdid_anchor="event"`; current code defaults to `"event_clean"`. Any re-run or resume of the ewatt arm under today's defaults will NOT reproduce the published numbers. Pin explicitly.
> - **Crashed runs leave ORPHANED `future` workers that starve every later run.** When a `run_scenario_grid` master dies, its multisession workers survive, spinning at ~35% CPU each, and are never reaped. Two crashed county gates left 8 orphans (~290% CPU total); the next run's master then sat at 0.0% CPU for 3.5 minutes of startup, and running jobs degraded from 55 s/batch to 8.5 min/batch before dying themselves — which manufactures the next crash, and so on. This *looks* like a memory leak in the master (that was the first, wrong diagnosis on 2026-08-25) but is CPU/RAM starvation by zombies from earlier failures.
>   **Operational rule: before launching or resuming any long run, check `ps -eo pid,ppid,lstart,pcpu | grep "[e]xec/R"` and `kill` any R process whose master is gone.** Orphans are safe to kill — their results can never be collected, and partials checkpoint per batch. Reaping the 8 orphans let a starved run resume from its checkpoint within seconds.
>   Root fix (unbuilt): have the runner register a `on.exit()`/signal handler that calls `future::plan(sequential)` or explicitly stops workers, so a dying master takes its workers with it.

**Reading notes.** (1) Run dates are `finished_at` times from `run_metadata.json`, not start times — consecutive runs can share a timestamp across rows. (2) For `county_cs_adaptive`, `size_gate.csv` is the authoritative file for the CS analytic arm (61.2% rejection); the same directory's `oc_summary.csv` analytic rows are a partial/misaggregated subset (rej05 = 0.06) — do not cite them.

## Adding a row

Per the maintenance rule above: **every completed run appends one row to the matching
table before the session ends.** Never delete a superseded row — change its status and
add a `→ replacement` pointer.

Template for a domain table row:

```markdown
| `run_name` | YYYY-MM-DD | `config/script path` | level / treat_def / weights / NV / panel-vintage | one-line headline number or finding | [`output(_blinded_power)/run_name/`](relative/path/) | STATUS (→ replacement, if superseded/contaminated) |
```

If the new run is a current best number, also add it to the **LIVE summary table** at the
top. If it replaces an existing LIVE row, move that row down into its domain table with
`SUPERSEDED → new_run_name` and delete only its line from the LIVE summary (never from the
domain table). If the run answers one of the [Open items](#open-items), resolve the item —
strike it or replace it with the answer, and note the resolving run's name.
